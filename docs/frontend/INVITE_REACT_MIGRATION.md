# Public invitation flow → React migration audit

## Decision

\`invite.html\` is a unique HIGH-risk public authentication surface. It must be migrated to React, but it must remain outside the authenticated business AppShell.

Canonical React route: \`/app/invite\`.

The route is public because a valid one-use invitation token is the credential required to preview and accept the invitation. It must not depend on an existing Helvoca session.

Legacy \`/invite.html\` becomes compatibility-only and must preserve the original query string when redirecting.

FRAME CHANGE: NO.

## Security / product contract

The invitation link contains:
- \`businessId\`;
- a high-entropy raw one-use token.

Backend stores only the SHA-256 token hash.

The public flow:
1. validates \`businessId\` + token through \`GET /api/v1/auth/invitations/{businessId}/{token}\`;
2. shows the invited business, person, email and role;
3. accepts only a new password with backend constraints 10..72 chars;
4. requires local password confirmation before POST;
5. calls \`POST /api/v1/auth/invitations/{businessId}/{token}/accept\` exactly once per explicit submit;
6. backend revalidates invitation state before creating the user;
7. on success stores the returned access token in sessionStorage and navigates to the canonical authenticated React app.

No password is ever generated or shown to the inviter.

## Invitation lifecycle truth

Possible preview states:
- PENDING: form is enabled;
- ACCEPTED: cannot be reused;
- EXPIRED: cannot be accepted;
- REVOKED: cannot be accepted.

The frontend must never turn a non-PENDING state into an acceptance attempt.

The backend remains authoritative against:
- reused invitations;
- revoked invitations;
- expired invitations;
- an email that already owns an account;
- invalid / missing token;
- invalid password length.

## Canonical link generation

New invitation links generated by \`TeamInvitationService\` should point directly to:

\`/app/invite?businessId=<id>&token=<raw-token>\`

This applies transitively to:
- Settings team invitations;
- PLATFORM_ADMIN assisted business provisioning;
- DEMO → PILOT conversion.

Legacy links already distributed as \`/invite.html?...\` must continue to work by redirecting with the full query string intact.

## React architecture

\`/app/invite\` is outside \`AuthBoundary\`.

Authenticated tenant routes continue to remain protected.

The invitation page gets its own compact public/auth visual composition:
- RecepVoz brand;
- invitation identity;
- password form;
- loading, invalid, accepted, expired and revoked states;
- no tenant sidebar/navigation.

## Legacy retirement

Retire:
- \`invite.js\`.

Keep:
- \`invite.html\` as a minimal public compatibility redirect preserving \`location.search\`.

Security allowlist keeps \`/invite.html\` and \`/app/**\` public at the document layer. Protected application routes remain guarded in React. Invitation APIs remain explicitly public in Spring Security and excluded from tenant DB context requirements.

## RED-first acceptance contract

1. \`/app/invite?...\` loads without an existing access token;
2. it previews a PENDING invitation;
3. it renders role labels consistently;
4. mismatched passwords perform zero POSTs;
5. explicit valid submit performs exactly one accept POST;
6. success stores the returned JWT and goes to \`/app\`;
7. ACCEPTED / EXPIRED / REVOKED states do not render an active acceptance form;
8. missing or malformed link parameters fail closed without an API call;
9. non-OK preview shows invalid-link state;
10. generated backend invitePath uses \`/app/invite\`;
11. \`/invite.html\` preserves query params while redirecting;
12. legacy page never loads \`invite.js\`;
13. authenticated routes are still behind \`AuthBoundary\`;
14. no real invitation is accepted during browser certification.

## Risk

HIGH because this is an unauthenticated credential bootstrap path.

Required evidence:
- RED browser contract;
- existing service/security tests;
- focused TeamInvitationService path assertion;
- Full Gate exact HEAD;
- exact-main CI;
- Railway exact-SHA startup/health/log verification.
